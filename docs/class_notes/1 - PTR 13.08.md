# 1 - PTR 13.08

- Seguir ESPECIFICAÇÃO
- HARD REAL TIME: Perder um prazo (deadline) é considerado uma falha do sistema. Se a resposta ocorrer após o prazo, o resultado pode ser inútil ou causar **danos graves**.
- FIRM REAL TIME: Eventualmente perder um prazo é tolerável, mas o resultado perde completamente o valor após o deadline. O sistema continua funcionando, mas aquele **resultado perdeu utilidade**
- SOFT REAL TIME: Perder prazos não causa falha do sistema. Apenas degrada a **qualidade do serviço**.
- "REAL REAL TIME" (informal): pior de todos os mundos - é um HRT com especificação temporal e **desempenho**
